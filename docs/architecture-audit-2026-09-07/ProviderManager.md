# Provider manager architecture audit

Acceptance criteria: one shared card-to-controller action path; duplication cannot mutate or activate the source; testing evidence is specific to the selected saved configuration; overlapping actions and late canceled results cannot commit UI state; existing native profiles and wire contracts remain compatible.

| Layer                       | Evidence and verdict                                                                                                                                                                                                                                                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 — Compilation             | Full frontend tests and `pnpm typecheck:fast` pass; no Rust source changes, so Cargo compilation is outside this diff                                                                                                                                                                                                                         |
| 2 — Dead code / duplication | Settings → ProviderProfileEditor → ProviderProfileLibrary callbacks → useProviderProfileEditor.act → existing RPC. Cards and form share one action dispatcher; duplicate helper is also used by Copy current connection                                                                                                                       |
| 3 — Naming                  | onNavigationBlockedChange replaces onDirtyChange at both production call sites and test fixtures, reflecting dirty OR busy state                                                                                                                                                                                                              |
| 4 — Semantic overloading    | Profile = saved configuration; draft = editor selection; configured connection = applied snapshot; receipt = evidence from testing. Selected styling and Test passed never imply active configuration                                                                                                                                         |
| 5 — Defaults                | Existing discriminated union has Codex plus the two Claude targets. Only Claude profiles inspect role mappings; Codex uses its explicit model. Failed reads are not rendered as an empty catalog                                                                                                                                              |
| 6 — Domain boundaries       | Library displays credential names/IDs from status; it does not read vault secrets or write harness files. Existing Claude/Codex field components continue to own their app-specific settings                                                                                                                                                  |
| 7 — Discoverability         | Card actions are named; editing fields open explicitly; duplication produces an unsaved draft. Active snapshot and pending revision labels preserve the existing distinction                                                                                                                                                                  |
| 8 — Wire / serialization    | Component-controller tests assert target/profile/model/receipt fields for Test and Apply, and force:false for Restore. DTOs, native serializers, persistence schema, and endpoint request protocols are unchanged. Existing expectedHashes construction was inspected and remains unchanged. No new live provider HTTP verification performed |
| 9 — Init parity             | All three app tabs mount the same keyed editor. Existing form and new card Test/Apply actions share act; tests exercise duplication for every target and existing app-specific fields. No new launch or session initialization path                                                                                                           |
| 10 — Resolver symmetry      | Search/metadata use the profile's keyId to resolve credential names. Default model uses the shared target-aware helper for both card metadata and RPC selection. Missing credentials remain editable but cannot Test/Apply                                                                                                                    |

The controller owns new action serialization. Previously, an overlapping action or edit could advance generation while an earlier operation still ran. A synchronous inFlight ref now rejects overlaps before awaiting; cancellable requests clear it explicitly, and only the matching generation can release it in finally. Tabs also remain disabled while busy. Cancellation/unmount retain existing native cancellation and stale-result guards.

The duplication boundary deep-copies nested settings, generates a fresh UUID, resets revision, and bounds localized names to the native 120-byte UTF-8 limit. Source profiles remain unchanged; only Save persists a duplicate. No historical data cleanup or migration is needed. Native revision/hash/receipt validation remains the authority for activation.

Not applicable: Rust refactors, session FSMs, orchestration, schema generators, database migrations, new external wire formats. No unrelated architecture sweep was included.
