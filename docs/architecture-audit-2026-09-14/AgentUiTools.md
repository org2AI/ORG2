# Agent UI tools — Codex-style usage layer

Scope: concrete native tools and the matching CLI facade over the existing 14-command broker. Acceptance criteria: short instructions, on-demand references, host-bound defaults, identical tool schemas/mapping across adapters, explicit terminal IDs, preserved authority/receipt ownership, no new background lifecycle. Methods: [architecture-audit](../../.orgii/skills/architecture-audit/SKILL.md) and [org2-performance-guard](../../.orgii/skills/org2-performance-guard/SKILL.md).

Ten-layer coverage:

1. Compilation: targeted Rust tests, Clippy and TypeScript checks; final commands/outcomes below.
2. Structural deduplication: traced native registration → `Org2UiTool` → shared prepare → broker and CLI call → same prepare → HTTP → same broker. Existing legacy actions remain intentionally compatible within the published feature.
3. Naming: canonical names in `core_types::tool_names`; a terminal resource ID differs from an agent session ID and a tab ID.
4. Semantics: open/presentation, content inspection, delivered input and command completion remain distinct; terminal reuse versus explicit creation have different target variants.
5. Defaults: native calling session; CLI complete host binding; explicit workspace override within the bound instance; no visible-session fallback. Facade reveal defaults true, raw CLI remains false.
6. Layering: `app_ui` adds only a dependency on the existing pure types crate for names. No Tauri, agent runtime, provider or launcher dependency enters the shared facade.
7. Discoverability: brief task-oriented instructions and examples; all reference index entries resolve. Deep protocol envelopes remain in the `protocol` topic.
8. Wire: inspected emitted tool schemas and actual CLI requests. No model-facing instance/protocol/timeout fields; schemas reuse existing bounds; request size cap remains 64 KiB. Strict empty variants reject previously ignored extras without changing valid JSON.
9. Init parity: native authority/management registration and CLI authenticated discovery retain their distinct trust boundaries, then converge on the same request/broker/handler. No adapter bypasses the existing frontend permission check.
10. Resolver symmetry: complete instance/window/workspace binding; CLI explicit flags replace environment binding, then optional tool workspace overrides only destination. Receipts are keyed by caller identity, not target workspace. Tests exercise both adapters.

Unrelated database, sync, React component and provider refactors are intentionally outside scope. No production action controls were added or changed in this increment.

## Integration findings

The [official Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs) lists supported string formats without `uri`. The model-facing browser schema omits that annotation and describes HTTP/HTTPS intent; the canonical Zod command schema and execution validation retain it. Provider-wire tests recursively check supported formats, unsupported composition keywords and required/closed nested objects. This keeps format adaptation at the tool-schema boundary rather than weakening URL validation.

The native request identity includes session, durable turn and tool-call IDs. Call IDs are only promised unique within a turn; reusing one in a later turn must dispatch a new request rather than replay an older receipt. The native boundary test covers same-turn deduplication, a distinct next-turn request with the same call ID, and same-session receipt access across turns.

Inspecting the final `responses_common::convert_tools` output revealed that both OpenAI Responses and Codex Native make optional properties required and nullable. The new facade initially rejected null workspace/reveal values. The shared decoder now treats only these optional nulls as omission, preserving caller binding and default presentation; required fields remain strict. Tests inspect the actual provider converter output and pass representative nullable arguments through the real native tool/broker boundary. This is serialized-wire coverage, not a live provider turn. The four native tests pass. A repeat CLI run also exposed an accepted socket inheriting nonblocking mode in the macOS fixture; accepted streams now explicitly use blocking reads, and teardown preserves the first failure instead of panicking again while unwinding. Production transport behavior is unchanged.

The full agent-core suite exposed missing tool detail metadata and incomplete canonical-name/renderer classification for the eight new tools. The metadata now reuses each shared description for its detail text. The canonical inventory lists all eight names; the renderer ledger explicitly keeps their bounded state/receipt text in the same generic block as `control_orgii`, since it is neither a process stream nor an artifact payload. Existing full-suite assertions are retained.

Integrating develop also required preserving separate reload cleanup: only main-window reload disconnects the UI broker; station-window reload uses the upstream window-scoped browser cleanup. The UI runtime fixture now supplies the upstream `isStationWindow` identity export. The four frontend suites pass 23 tests with the updated Vitest version; shared/CLI suites pass 29 tests and native boundary tests pass 4 tests. CI on `4a9f6269c` passed all 17 checks, including 8,012 Rust tests and 14,009 frontend tests. The first frontend attempt had one unchanged Runtime panel lazy-loading assertion fail; its nine tests passed locally and the full frontend rerun passed without code changes.

A subsequent integration of develop at `57200d724` preserves the upstream traffic-light observer teardown for every destroyed window alongside the main-only UI broker disconnect. Neither cleanup replaces the other. The diff against that base adds only the two existing main-specific broker disconnect blocks to `lifecycle.rs`. Final checks after this integration are recorded in the PR.

## Compatibility and rollback

The version-1 broker and 14 command IDs remain unchanged. The catalog hash changes with discovery tiers, so CLI/app builds must match. Existing `control_orgii` and raw CLI remain available; their ordinary parameter and reveal behavior is preserved. The shared facade adds one internal crate dependency, no external dependency or persisted-state migration. Roll back this increment by removing the facade tools/CLI call and host-binding additions, restoring the catalog/rulebooks and tool registration/policy entries. Existing tabs, terminals and protocol clients need no data migration.
