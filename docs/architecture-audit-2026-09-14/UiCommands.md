# UI commands — architecture and lifecycle review

Methodologies: [architecture-audit](../../.orgii/skills/architecture-audit/SKILL.md) and [org2-performance-guard](../../.orgii/skills/org2-performance-guard/SKILL.md).

Scope: the new public `app_ui` broker, authenticated loopback adapter, console CLI, document-owned frontend receiver, six semantic commands, shared rulebook and sidecar packaging. Existing session/reply ActionBridge behavior and unrelated workstation/button edits are outside this change.

## Ten-layer coverage

| Layer                     | Evidence / disposition                                                                                                                                                                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 Compilation             | Frontend typecheck and scoped lint; Rust unit tests, app all-target check and leaf-crate clippy. Commands below.                                                                                                                                 |
| 2 Dead code / duplication | Public callers traced CLI → HTTP / native tool → broker → one Channel → registry → adapter. All new exports have callers. Legacy ActionBridge intentionally retained, not labeled a completed migration.                                         |
| 3 Naming                  | `ui.*` names the published semantic surface; `gui.*` remains internal legacy tooling. `sessionId` is workspace identity; Browser result has `browserSessionId`.                                                                                  |
| 4 Semantic overloading    | Request target and caller authority are distinct. Workspace/shared tab partition is explicit. `applied`, readable, loading and rendered presentation remain separate concepts.                                                                   |
| 5 Defaults                | Main window only; mutation workspace required; context defaults global envelope but reports presented context. No implicit new app instance or agent session. Target-file cannot mix workspace/window flags.                                     |
| 6 Domain boundaries       | `app_ui` contains protocol, broker and published catalog/docs. Tauri and OS file checks live in app adapters. Agent authority remains in the native tool. CLI has no agent-core dependency.                                                      |
| 7 Comprehensibility       | Short rulebook plus discoverable docs; implementation README distinguishes supported commands and future design. No leaked generation/token needed in agent requests.                                                                            |
| 8 Wire protocol           | Strict Serde/Zod envelopes; shared fixture roundtrip; catalog regeneration check; request/response size limits; actual HTTP route test. No broad internal action-schema dump.                                                                    |
| 9 Init parity             | Matrix below. Found and fixed CLI TLS setup and provider placement of the React receiver.                                                                                                                                                        |
| 10 Resolver symmetry      | Both adapters deserialize the same Request and use identical target/permission/file-resolution behavior. Absolute paths are explicit; relative paths resolve from the selected repository, never CLI cwd. No fallback to another session/window. |

All ten architectural layers were reviewed for the changed surface. Database migrations, provider-history ingestion, cloud sync, session lifecycle and React streaming optimization are not involved. No frontend control/style audit was run: the only production TSX change mounts a nonvisual hook, and no action controls were added.

## Performance guard

| Area               | Verdict | Evidence                                                                                                    | Change or reason kept                                                                                                           | Verification                                                                                                 |
| ------------------ | ------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Background work    | keep    | One document Channel; no polling, retry loop, watcher or worker added                                       | Register only on main; unregister on unmount; Rust disconnect on page-load start/destroy                                        | 5 React lifecycle/browser tests; broker reload/cancel tests                                                  |
| Memory             | fix     | Pending 50, receipts 256 / 60s, body 64 KiB; frontend queue 50; transient Browser refs 50                   | TTL pruning is demand-driven; clear transient refs after Browser source commits or receiver disposes; no periodic cleanup timer | Pending-capacity, concurrent duplicate, receipt-cap/TTL tests; repeated-URL React test                       |
| Scope/isolation    | fix     | Request includes instance/window/workspace; full request + generation checked before async commit           | Target session never sets caller identity; CLI descriptors confined to selected home; mismatched instance/main target rejected  | Broker wrong-target/caller/forged-payload tests; production HTTP auth test; executor permission/target tests |
| Rendering/hot path | keep    | Receiver is under BrowserProvider, using refs; serial requests; no streaming-state subscriptions introduced | BrowserContext remains the resource owner; only transient pre-commit references added                                           | React tests only; no CPU/RSS or real visible/hidden measurements                                             |
| Blocking I/O       | keep    | File preparation and descriptor publication use spawn_blocking; CLI scan is on-demand and bounded           | Requests expire rather than retrying in background; regular-file guard avoids opening known FIFOs                               | Actual temp-file test and CLI smoke; stalled remote-filesystem I/O is not measured                           |

| Lifecycle dimension                                    | Required behavior / coverage                                                                                                                                                                          |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start / reload / unmount / late register               | One current generation; old requests become unknown; late writes rejected. Unit and React tests.                                                                                                      |
| Idle / hidden / focus return                           | No scheduled discovery or polling. Channel remains available for explicit commands while hidden. Source inspection only; actual idle CPU/RSS not measured.                                            |
| Active / burst / timeout / cancellation                | Serial frontend queue, bounded broker pending, one execution per retained identical request, unknown receipt after timeout/cancel. Unit tests.                                                        |
| Session active / inactive / deleted / repo replacement | Explicit destination retained; deletion or replacement before async commit rejects. Executor tests. Browser inactive workspace explicitly unsupported.                                                |
| Instance primary / secondary / restart                 | UUID target and home-isolated discovery; missing/old instance never silently retargeted. Broker tests and empty isolated-home CLI smoke; live dual-instance test not run.                             |
| Account / cloud endpoint / provider sources            | Not a cloud/provider feature; local OS-user trust only. Does not claim account-specific sandboxing or provider-launch compatibility.                                                                  |
| Shutdown / abnormal exit                               | Listener Drop removes own descriptor where shutdown runs; stale descriptors fail identity/token handshake; no persistent request replay after restart. Source inspection and broker disconnect tests. |

**Performance verdict: blocked** for real Tauri visible/hidden idle, active CPU/RSS, post-close measurement and primary/secondary presentation. Repository policy requires explicit Computer Use opt-in, which was not given; no desktop-control API was invoked. Static bounds and unit results are verified, but are not runtime performance evidence.

## Compatibility and rollback

No database/config migration or personal harness configuration changes. New protocol is version 1 and requires matching catalog hashes; a stale CLI reports mismatch. CLI discovery failure only disables the new discovery surface and does not stop the existing IDE server. Legacy GUI/session paths remain available.

Rollback removes the new hook/routes/entry branches, native public adapter + shared prompt injection, workspace crates and `org2-ui` sidecar entry. No persisted tab state migration needs reversing; tabs use existing factories/state. Old endpoint files contain ephemeral credentials and cannot authenticate a new process. Preserve unrelated workspace edits when reverting this feature.

## Terminal extension (same day)

The user explicitly extended scope to terminal command execution, literal input and interrupt. The public catalog now has 14 commands: the initial six plus `ui.terminal.open`, `new`, `list`, `focus`, `read`, `execute`, `input`, `interrupt`. The shared short rulebook is 602 words / about 4 KiB; detailed terminal behavior lives in `docs terminals` / `docs/agent/ui/terminals.md`.
