# Hooks and atoms reachability audit

Date: 2026-09-22. Scope: the pre-cleanup TypeScript working tree under `src/`, desktop and mobile entry points. Line numbers in the candidate tables refer to that baseline.

Implementation note (2026-09-22): The confirmed dead atoms and TypeScript barrel routes below were removed, the legacy inbox writer was reduced to its live database write, and the run-group selector cache was bounded. A second pass removed two more unused workstation atoms, 37 unused default hook aliases, and two orphaned barrels. The six remaining TSX-only re-export routes to live implementations were then removed; the hook/atom unused-export scan now reports no findings in that category.

## Result

There is worthwhile dead-atom cleanup. No confidently dead production hook implementation was found in this pass. Many hook exports are unused barrel routes to implementations imported directly elsewhere. Do not delete those implementations.

Acceptance criteria for this review: distinguish implementations from barrel exports; exclude tests/comments/debug labels as runtime consumers; check aliases and dynamic imports; trace representative live owners; identify storage/side-effect boundaries before recommending deletion. This is a candidate inventory, not proof that every remaining declaration is live.

## Verification and limits

- `pnpm typecheck:fast` — passed, exit 0 on the existing working tree.
- `pnpm exec knip --config config/knip.json --include files,exports,nsExports --reporter json` — completed, exit 1 because unused items were reported. Tests are configured as entries, so this is not sufficient evidence of production liveness.
- Additional production-entry Knip scan using a temporary configuration and `--production`, with test files excluded — completed and used as corroboration. Development/mobile platform files reported by this scan were not classified as dead; plugin entry inference and platform configuration require separate treatment.
- TypeScript AST inventory over non-test source: 2,398 hook/atom-named declarations. Ignored imports, re-exports and debug-label references when finding zero-consumer candidates. Manually checked aliases/member calls and read candidate implementations and live owners. This inventory is name-based, not a full symbol-level reachability proof.
- Repository reference searches distinguished tests, comments, labels, exports and executable consumers. No tests were changed or run; no code was deleted, so this is not post-removal verification.
- No GUI automation, Rust compilation, runtime profiling, network calls, database reads or storage cleanup performed. No performance improvement is claimed.

Knip's `ignoreExportsUsedInFile: true` allows `.debugLabel` self-references to hide unused atom exports. A future atom-specific check should ignore diagnostic assignments, follow alias/re-export/member usage, and classify reads versus writes. Globally flipping that setting without measuring noise is not recommended by this audit.

## Architecture coverage

1. Compilation: frontend typecheck passed; Rust skipped for this frontend audit.
2. Dead code/deduplication: primary focus, including test-only and transitive dead chains.
3. Naming: stale compatibility/public-path comments noted.
4. Semantic overloading: selected/current branch and legacy/TeamInbox distinguished.
5. Defaults: inspected relevant `main`, storage and selector defaults; no repo-wide branch audit.
6. Boundaries: distinguished durable inbox writes from unused UI cache and live EventStore ingestion from obsolete mutation wrappers.
7. Discoverability: unused barrel API surface and misleading usage comments identified.
8. Wire: no wire change proposed; actual payload inspection intentionally not performed.
9. Initialization: lazy root services and separate window bridge mounts checked for false positives; no full cross-platform init audit.
10. Resolver symmetry: preserved live workspace resolution and simulator snapshot/fallback paths; no resolver refactor proposed.

Recommended order: remove obsolete event/simulator atoms; remove small unused atoms and test-only actions; trim remaining barrel exports; handle legacy inbox persistence separately. Removal implementation touching queue/cache/storage/lifecycle must apply `org2-performance-guard` and run affected boundary tests. This audit changes none of those behaviors.
