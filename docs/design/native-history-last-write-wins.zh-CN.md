# 原生历史同步：后写覆盖，原样保留

日期：2026-09-23

状态：用户已确认产品取舍；本文是实现与验收依据，**实现已按本方案替换，完整产品原生验收仍待完成**。

关联 PR：https://github.com/org2AI/ORG2/pull/2103

## 1. 已确定的目标与取舍

同一台机器上，同一种原生客户端的 1P 环境和 ORG2 管理的 3P 环境共享会话历史。

- 按单个会话同步，不覆盖整个数据库、用户目录或 profile。
- 一边变化时，以变化的一边为准。
- 两边都变化时，采用后写入的一份；不合并消息，不要求用户选择冲突版本。
- 不为被覆盖内容保留旧快照、版本备份或恢复入口。
- 用户接受：同时在两边续聊时，较早一份中独有的消息可能被覆盖且无法恢复。
- 消息正文、工具调用与结果、原生 UUID 及附加字段尽量按原始字节保留，不经过 ORG2 的转录格式重建。
- 不使用 App 发布版本白名单，也不因为出现未知消息字段而阻止原生历史同步。

这是同一客户端的两个环境之间的交接，不是 Claude 与 Codex 之间的格式转换。

## 2. 为什么调整现有实现

当前 Claude 首次导入已经原样复制转录；后续回写却先校验字段白名单，再筛选运行记录、重写父子关系并维护转换记录。两条路径承担了不同的语义。

真实 Claude Code 2.1.281 能正常读取、续聊和保存测试历史，ORG2 的生产解析器却拒绝它生成的部分记录。因此，这次失败首先说明 ORG2 的转换规则不兼容，不能据此认定原生程序的两个环境互不兼容。

新方案把两项职责分开：

| 层            | 职责                                                 | 未识别内容的影响                       |
| ------------- | ---------------------------------------------------- | -------------------------------------- |
| 原生历史同步  | 完整性、会话归属、更新顺序、安全发布、必要的原生索引 | 普通消息附加字段原样保留               |
| ORG2 转录展示 | 为 ORG2 界面提取可展示内容                           | 可报告预览不支持；不能据此阻塞原生同步 |

不再为了同步维护完整的消息字段模型或自行推断每种工具的执行语义。

## 3. “后写入”的明确含义

比较同一会话两侧的**稳定原生数据修订**，不是比较 App 版本号，也不是比较整个数据库文件的修改时间。

1. 记录上次观察及发布的会话内容哈希和修订信息。
2. 哈希不变，即使文件修改时间变化，也不算新修订。
3. 两边都出现新修订时，以会话数据最后稳定写入的时间选择胜者。
4. 时间相同且内容不同，采用固定规则：1P 为准；记录选择结果，避免来回覆盖。
5. ORG2 自己的复制、索引登记和恢复操作不得被识别为新的原生编辑。发布记录必须绑定胜出修订和目标结果。

这里的“更新”是数据写入顺序，**不是最后一句真人消息的时间**。不解析所有消息语义，就不能保证区分新增对话与每一种原生运行状态更新。验收必须包含“只打开会话”的情形，并记录实际行为；不能悄悄增加另一套完整字段白名单来判断新旧。

如果无法取得一致快照或有效的修订证据，应等待或报告同步失败，不能凭不完整文件猜测胜者。

## 4. 同步状态规则

| 观察结果                   | 行为                                             |
| -------------------------- | ------------------------------------------------ |
| 两侧内容相同               | 不操作                                           |
| 相对已知基线只有一侧变化   | 该侧覆盖另一侧                                   |
| 两侧都变化                 | 按第 3 节选择胜者，覆盖另一侧                    |
| 目标正在被原生程序写入     | 等待可安全发布的时机，重新观察后再决定           |
| 复制过程中任一相关修订变化 | 放弃本次提交并重新观察，不发布过期胜者           |
| 源文件压缩、重写、截断     | 获取完整、稳定的会话快照；不把它误作普通追加     |
| 一侧会话不存在             | 在归属和索引条件明确时导入存在的一侧             |
| 用户删除或归档会话         | 不从文件缺失推断覆盖或级联删除；删除传播另行定义 |

不做文本合并、消息拼接或自动拼接两个不同分支。可证明目标是完整旧前缀时可以优化为原始增量复制，但结果必须与完整快照交接一致。

## 5. 发布与临时空间

- 先在目标文件系统写完新内容，验证源修订和目标预期状态，再原子发布。
- 不额外复制被覆盖的旧文件作为备份。
- 只允许发布所需的新内容暂存、必要的事务记录和原生数据库自身的事务机制。
- 成功后清理已完成事务的暂存文件；未完成事务有明确的恢复、失效清理和空间上限。
- 多文件和数据库索引更新不是一次文件 rename 就能原子完成。必须定义中断后的继续提交或安全停止，不能报告部分发布为成功。
- 文件发布的原子性不能代替原生写入协调。发现目标仍在使用或无法建立所需协调边界时，暂缓发布。

“无备份”指不保存可供用户找回旧对话的额外副本，不表示可以直接截断正在使用的文件。

## 6. 原生分叉依赖不是备份

如果一个旧物理历史文件仍被原生子会话、冻结分叉或待完成事务引用，它仍是有效会话数据，不能因为主会话已经更新就删除或改写。

Codex 已观察到子会话依赖旧物理历史及其索引。新方案必须保留这项原生语义：逻辑会话采用后写覆盖，不等于能够覆写所有旧物理文件。

此类必要依赖不属于用户否定的“覆盖前自动备份”。自动回收仍需要证明没有有效引用；不能用文件年龄、没有当前列表项或一个瞬时进程检查替代证明。

## 7. 配置隔离与最小适配

账号、凭据、套餐、API endpoint、权限配置继续由各自环境管理，不随会话覆盖。

原生转录可能保存 prompt、工具上下文和其他会影响续聊的状态。原样交接后，必须实测目标环境仍使用自己的连接与授权配置；不能默认原样复制就已经证明路由正确，也不能通过静默丢弃历史内容制造通过结果。

原生目录和索引优先由原生接口注册或重建。若必须直接操作数据库，只保留该操作所需的结构适配和完整性检查，并保留无关数据。不要依赖完整数据库的固定列清单来判定所有操作是否支持，也不能盲目复制未知关联表或抛弃未知列。

同一安装通常产生相同格式，但两个进程可能跨越升级、两侧数据库也可能尚未完成同一迁移。遇到实际结构差异时交给原生迁移或暂停相应操作；不恢复按发布版本锁定的设计。

## 8. 代码调整范围

在证明原生交接方案成立之后，删除原生同步路径中被替代的：

- 普通消息字段白名单和工具名称准入表。
- 为同步重新序列化消息、筛选正文、重写消息父子关系的转换逻辑。
- 仅用于解释上述转换差异的记录及相应测试。
- 基于完整消息解析结果阻断同步的依赖。

保留或收敛：会话身份与归属、原生发现与索引、必要的依赖处理、运行中写入协调、内容哈希、胜出修订记录、原子发布、崩溃恢复、资源预算和事件驱动调度。

ORG2 展示转录所需的解析器继续存在。删除转换记录前需要处理现有 journal 的恢复和迁移，不能直接抹掉未完成操作或假定旧记录从未存在。

## 9. 验收要求

先用隔离的原生环境验证设计，再替换生产同步路径。不得用手工修改目标历史、伪造目录注册或独立探针调用，代替真实产品按钮流程。

每种客户端分别完成：

1. Configure → Open → 历史列表显示 → 打开历史 → 续聊 → 自动回写 → 重开。
2. 1P → 3P 和 3P → 1P 两个方向的历史完整性与实际请求路由。
3. 两侧同时修改：后写者胜出，结果唯一且重复同步不来回切换。
4. 内容相同但修改时间不同、只打开会话、连续切换和重启。
5. 目标正在写入、发布中断、原生文件重写或压缩。
6. 工具结果对应原调用，已完成工具不因恢复历史再次执行。
7. 原生分叉和仍被引用的祖先在覆盖后依然可读、可续聊。
8. 覆盖不创建旧快照备份；完成事务清理临时文件；空闲不反复扫描。
9. ORG2 展示解析不支持一个字段时，原生交接仍可成功。

保留手动运行的原生交接、索引可见性和续聊回归测试；本 PR 不再维护自动下载最新版、定时探测和 issue 通知。新增字段本身不应使测试失败；区分真实行为失败与无法完成测试。
