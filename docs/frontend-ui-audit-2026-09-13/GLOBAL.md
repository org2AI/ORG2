# GLOBAL — Button adoption audit

Updated after the September 13 button migration. This replaces the pre-migration inventory.

**All 444 previously inventoried raw JSX button sites in 278 files now render the reusable Button.** Of these, **150 ordinary actions** use its standard presentation (109 icon controls and 41 text/action controls); **294 compound controls** use the explicit custom layout and appearance to preserve their existing UI. The custom mode is not a claim that those controls now use the standard Button visual treatment.

Scope: source JSX under `src`, excluding tests, fixtures, comments and example strings. Counts describe source sites, not rendered instances. The 15 previously inventoried literal button-role elements were not native button sites and are outside this migration.

## D2 — Arbitrary values vs tokens

Standard actions use Button variant, appearance, size and icon props. Compact header actions use sidebar sizing; search toggles use primary/tertiary ghost appearance and aria-pressed. Menu rows, tabs, cards, swatches, window chrome, editor controls and composite primitives retain their existing surrounding surface classes. This change does not assert that every retained local style is standardized. No global token sweep was performed.

## D3 — Hardcoded sizes and colors

Compound layout prevents Button from imposing fixed dimensions, padding, typography or a label wrapper on controls whose parent layout or CSS owns their shape. The inline size keeps text actions at intrinsic height and allows surrounding typography. Sub-20px embedded icon hit areas retain explicit dimensions where required by their existing slot. Actual visual appearance has not been verified in the desktop app.

## D4 — Accessibility basics

Standard icon actions with an existing title gain the same accessible label where one was absent. Search options expose pressed state; their callbacks and conditional visibility are unchanged. Native disabled behavior, switch semantics, direct child structure and refs are covered by rendered tests. Button applies its explicit htmlType after passthrough attributes so wrapper spreads cannot override it. The existing non-button expand chevron and other role-based controls are outside this native-button inventory.
