## Architecture review

Acceptance: pane layout and controls must not depend on active tab type; one station exception owner and one chat-focus control; all chat tab types support split and maximized states; detached/Settings/pinned ownership remains explicit; no removed policy references remain.

Layers 1–7: TypeScript and lint checks; deleted stationAccess, its availability/maximize resolvers and the guarded active-tab toggle; actions call the canonical pane toggle. Restore-chat and restore-workstation remain distinct actions. The station-mode input selects the visibility key and detach destination, not tab-specific behavior. The shared exception component exposes only stationMode. Project search remains outside it.

Layer 8: no IPC, schema or persistence-format changes; saved maximize preferences retain their meaning. Layer 9: My Station and Agent Station share window policy; chat and pinned chrome share the focus button; service/shortcut actions and UI actions reach the same maximize atom. Layer 10: effective layout reads only the saved pane preference; active-tab state is no longer a competing fallback or override.

Historical remediation: none needed. The removed layout override was derived and did not overwrite the saved preference. Restoring the old source behavior is sufficient to roll back; no data migration is involved.

## Update 2026-09-17: tab-level Station access restored

The "Tab-specific pane restrictions" fix above was reverted at the product owner's request. `stationAccess` is back on `CHAT_PANEL_TAB_TYPE_POLICY`: session, terminal, Launchpad, channel and run-group tabs may sit beside a Station; Runtime, Work (Inbox / Kanban / lists), workspace, organization, work-item, GitHub issue/PR, project and explore tabs always own the full workbench. `effectiveChatPanelMaximizedAtom` again derives from the saved preference plus the active tab, `toggleActiveChatPanelMaximizedAtom` guards every toggle path, and `WorkStationViewService` rejects show-workstation / open-station actions for those tabs. The shared `ChatPaneFocusButton` reads the policy itself and renders disabled with `chat.workstationUnavailableForPage`, so the consolidated header controls from this audit are kept.
