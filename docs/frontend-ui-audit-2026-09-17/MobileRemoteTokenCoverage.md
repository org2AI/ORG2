# Mobile Remote token coverage audit

Scope: the current mobile worktree, including `src/modules/MobileRemote` screens, auth, chrome, profile, transcript, composer, changes, and their directly used shared controls. Also inspected browser/native bootstrap and the iOS window/launch configuration. This is not an audit of every Desktop page or every native dependency. Two parallel agents inspected pages and chat; the primary agent checked shared overlays, bootstrap, and consolidated overlapping findings.

Source-only audit. No production code changed. Prior dirty changes remain untouched. Priorities below describe token adoption and consistency; they do not assert a reproduced rendering failure.

## D4 — Accessibility implications

The composer hit-target finding and QR input focus-size finding above are counted once under D3. Shared BottomSheet's source default close size is 32px, but `src/modules/MobileRemote/mobileViewport.scss:97` already overrides it to the 44px mobile token. It is **not** an outstanding 32px touch-target defect. This audit did not test modal focus trapping, screen reader navigation or keyboard behavior, and makes no full accessibility-conformance claim.

## Summary and recommended order

Verdict totals: **5 fix candidate**, **7 keep with reason**, **3 abstract**. The three abstract findings are cross-component sweeps, counted once each; the typography hotspot list is not additional findings.

1. Repair invalid error color mapping, pairing-input typography/protection and settings-error typography; these are narrow, directly evidenced omissions.
2. Unify mobile overlay presentation and composer touch density.
3. Adapt shared typography at its control boundaries, including portaled menus; avoid changing Desktop defaults.
4. Bridge native/browser chrome to appearance, then verify cold launch and theme switching.
5. Consolidate remaining equivalent spacing tokens without changing intentional layout dimensions.

### Verification performed

- Read mobile consumers and owning shared implementations; traced inline Button styles, descendant typography and mobile SCSS overrides rather than counting regex hits alone.
- Inspected raw element matches: hidden file input is a genuine browser boundary; no raw production button match in MobileRemote.
- Ran `pnpm test src/modules/MobileRemote/mobileTypography.test.ts`: **2 passed, 1 failed**. The failure identifies `screens/settings/SettingsTab.tsx:160` using `text-xs`; token declaration/compilation checks passed.
- No simulator/browser computed-style or screenshot verification in this audit. Native launch flash, browser chrome appearance and iOS input zoom are risks requiring runtime checks, not reproduced defects.
- No production edits, data changes, release, commit or PR were performed. Future shared-component changes should validate light/dark themes, narrow screens, portal surfaces and Desktop consumers before delivery.
