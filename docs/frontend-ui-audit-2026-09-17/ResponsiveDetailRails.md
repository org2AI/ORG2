Lifecycle matrix: mount/resize/unmount and repeated tab changes are covered by component and measurement-hook tests. Hidden panes retain their existing layout at zero width and are remeasured when shown. Initial PR loading and closed properties disable their existing detail measurement. Header hosts use one observer and resize fallback each; they unregister at zero width, at 700px or wider, and on unmount. The store-local host array is bounded by mounted narrow headers and retains no data across app restarts. An already-open sidechat retains its existing behavior. Offline/auth/provider/transport state is unaffected. Each app instance owns independent refs. Visible/hidden idle CPU and RSS, repeated desktop open/close, focus-return geometry, and screenshots were not measured: the user has not opted into computer control.

Performance verdict: **blocked** for real-app measurement; automated lifecycle checks pass. No runtime performance improvement is claimed.

Resize regression coverage verifies the 699px/700px boundary, one mounted properties instance, title/properties/timeline ordering, composer inset and PR tab switching. Sidechat regression coverage verifies one blue header launcher at 699px, one floating launcher at 700px, zero-width removal, remount handling, and observer cleanup. No rendered desktop screenshot or CPU/RSS measurement was taken.

Risk: crossing the breakpoint remounts the property editors, which can close an open dropdown; saved values and parent-owned conversation drafts remain with their existing owners. No persistence, API, dependency, or data format changes. If several visible detail headers are narrow, the single global launcher uses the most recently registered eligible header; disposing it restores the previous eligible host.
