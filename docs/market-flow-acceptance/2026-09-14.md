# Market app connection acceptance — incomplete

## Product boundary

Seller account enrollment should stay on the website. Buyers use ORG2 to configure their chosen native client or launch an ORG2 workspace. A dispatched deep link, saved profile, and successful inference are three distinct acceptance steps.

## Implemented in this checkout

- Claude App is available as a Market connection target and uses the existing owned native Desktop configuration writer.
- Desktop receives a credential-helper path and purchased Claude model catalog. It receives neither a static Market bearer nor a refresh token in its configuration. The helper invokes the existing headless ORG2 authentication entry point, which renews on demand.
- The helper uses Desktop's `inferenceCredentialKind=helper-script`, `inferenceCredentialHelper`, and 60-second TTL, observed in the installed app's Connection settings. CLI installation is not required to open Desktop.
- Opening a workspace uses the documented `claude://code/new?folder=...` link through the Claude bundle. Desktop may require restarting to load changed third-party configuration and confirms the folder itself. This is not proof of ordinary Chat support.
- Disconnect restores only the matching owned native configuration; an unrelated replacement selection is preserved. Default mode remains a no-op. The native configuration writer retains backup/conflict checks.
- The Market proxy preserves explicit request model IDs instead of silently rewriting them to the selected default. The ORG2 placeholder still resolves to the default. The Market gateway remains responsible for entitlement/model authorization.

## Verification

- `cargo test -p agent_cli managed_config --manifest-path src-tauri/Cargo.toml`: 59 passed, including helper generation, all-model catalog, no static bearer, conflict protection, and disconnect restoration.
- `cargo test -p org2 --features market-connect cli_managed_proxy::tests --manifest-path src-tauri/Cargo.toml`: 13 passed. The loopback HTTP regression checks actual forwarded bodies for the default placeholder and two explicitly different models.
- `pnpm test src/features/MarketConnect/ConnectionDialog.test.ts src/features/MarketConnect/launch.test.ts`: 21 passed.
- ORG2 and Console TypeScript checks passed. Local desktop webpack/Tauri build succeeded.
- Chrome displayed the translated Claude App connection button and existing synthetic multi-model purchases. Native Chrome actions were repeatedly interrupted before the authorization/configuration flow completed.

## Not accepted yet

- End-to-end new profile application, restart behavior, and real inference in Claude App or ORG2.
- Actual supplier token renewal, model-by-model charges, and paid business acceptance.
- Windows native launch; the new Market Desktop adapter fails explicitly outside macOS.
- Production seller browser-only subscription OAuth: current CPA clients use fixed localhost callbacks (Claude 54545, Codex 1455). No registered Market HTTPS callback has been identified. Local-server loopback reception is not evidence of a production browser-only solution. Existing seller flow is retained pending a supported authorization transport.

## Runtime characteristics

No new polling worker, proxy server, or credential cache was added. The generated helper runs only when Desktop invokes it; existing grant refresh logic owns renewal. Configuration files contain public selection metadata and an executable path; the existing OS credential store owns the authorization. Real hidden-window/quit/restart acceptance remains pending.
