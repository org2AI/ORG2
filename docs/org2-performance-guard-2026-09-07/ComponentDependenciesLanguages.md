# CodeMirror language loading performance guard

| Area               | Verdict | Evidence                                                                                                                                                 | Change or reason kept                                                                                                              | Verification                                                                                      |
| ------------------ | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Background work    | fix     | Parser loading begins on a hook's non-JS language demand; no polling, retry timers, subscriptions, workers or scans                                      | Concurrent consumers share one in-flight language promise; completion clears the pending entry; errors retry only after new demand | Concurrent identity and failed-construction retry tests                                           |
| Memory             | keep    | Successful extension caches have a 64-entry hard cap and are naturally bounded by the supported language set; pending requests accept only registry keys | Retain process-scoped immutable parser configuration; no documents or identity data retained                                       | Cache bound/eviction, repeated language reuse and 100 unknown language requests                   |
| Scope/isolation    | fix     | Hook owns each async continuation separately from language-name identity                                                                                 | Cleanup invalidates completion after language changes and unmount; module cache is deliberately shared across editor instances     | A → B → A, StrictMode replay, no-language transition and unmount tests                            |
| Rendering/hot path | fix     | Old eager module statically imported ten non-JS parser packages                                                                                          | Detection is parser-free; hook uses the JS/TS-plus-dynamic-import module; Diff/ConflictEditor stay synchronous                     | Import-graph regression, all 24 filename mappings, isolated Webpack development/production builds |

## Lifecycle matrix

| State                                                       | Required behavior                                                                | Evidence                                                               |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Unopened / app startup                                      | No language request from this hook until mounted with a non-JS language          | No module-scope load; synchronous/no-language tests                    |
| Active JS/TS editor                                         | Return synchronous extension; no lazy request                                    | Hook synchronous-language test                                         |
| Active non-JS editors                                       | Share requests by language; cache successful results                             | Single-flight and reuse tests                                          |
| Language switch / replay                                    | An earlier effect cannot commit after its cleanup                                | A → B → A, no-language and StrictMode tests                            |
| Unmount / close                                             | Ignore completion; release in-flight entry when import settles                   | Unmount and settled-result reuse tests                                 |
| Failure / offline chunk error                               | Return null and retain no failed cached extension; no automatic retry loop       | Failed-construction retry test; real offline chunk fetch not exercised |
| Visible / hidden / focus return                             | No added periodic work; an already-started import may finish while hidden        | Static lifecycle review only; real Tauri CPU/RSS not measured          |
| Account / endpoint / org / multiple windows                 | Parser cache has no identity or document content; each JS process owns its cache | Ownership review; no account-scoped resources introduced               |
| Provider history / cloud transport / raw source transitions | Not applicable                                                                   | No ingestion or sync paths touched                                     |

Verification: 39 focused CodeMirror tests, changed-file ESLint and full-project `pnpm typecheck:fast` pass in the independent branch. See [architecture evidence](../architecture-audit-2026-09-07/ComponentDependenciesLanguages.md) for exact commands and isolated build measurements. Development initial fixture output decreases 549,558 bytes; production already splits the language chunks and does not decrease. This is not a measured whole-app startup or memory improvement.

Performance verdict: blocked for live Tauri measurement and real offline chunk-fetch behavior (computer control not authorized); bounded retention, single-flight requests, stale-result rejection and isolated chunk boundaries pass their applicable automated checks. No unbounded or cross-identity resource was found.
