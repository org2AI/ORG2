# Image preview modal lifecycle review

| Area               | Verdict | Evidence                                                                                                                                              | Change or reason kept                                                                                                                                    | Verification                                                                   |
| ------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Background work    | keep    | Viewer exists only while open; shared ModalSystem owns focus timer and document Escape listener                                                       | Removed the preview-specific global key listener; arrow handling is scoped to the React modal event tree; no polling, retry or preload loop              | Existing modal lifecycle tests and preview Escape/unmount test                 |
| Memory             | keep    | Gallery is metadata references owned by one attachment row; viewer retains one selected result in addition to the opening thumbnail's existing source | Resolve on navigation only; no completed gallery cache; release owned Blob URLs on replacement/close and late completion; never revoke caller-owned URLs | Selected-only, late-result, owned-URL and borrowed-URL tests                   |
| Scope/isolation    | keep    | Gallery ordering comes from the same message's images prop                                                                                            | No global registry, conversation scan, persisted metadata or cross-session cache                                                                         | Thumbnail production-boundary test opens the selected index and exact row list |
| Rendering/hot path | keep    | One memoized metadata projection per changed row list                                                                                                 | Navigation updates only the mounted viewer; no eager decode or new provider history load                                                                 | Read-call assertions; no desktop performance improvement claimed               |

Lifecycle matrix: unopened/closed/inactive sessions create no new viewer resources. An open visible or hidden viewer has no recurring background work; a pending selected-image read can finish while hidden. Focus return adds no fetch. Closing/unmounting invalidates late completions and releases owned URLs. Read/decode failure leaves previous/next and close usable; no automatic network retries are added. Account/session teardown follows the existing parent unmount boundary. Primary/secondary instances share no new state. Provider ingestion, source append/rotation, persistence and cloud transport are unchanged by this UI work.

Verification: targeted viewer, thumbnail, Markdown image and ModalSystem tests; frontend typecheck and changed-file ESLint. The UI audit records chrome reuse and responsive dimension rationale.

Performance verdict: blocked for live desktop/WebView memory and visible/hidden lifecycle measurement because computer control was not authorized. Unit evidence covers selected-image loading, cancellation and URL ownership; no measured RAM improvement is claimed.

Zoom follow-up: the floating footer uses the shared Slider with 25–400% bounds, plus minus/plus and reset controls. Zoom changes layout dimensions of the existing image in a scrollable viewport; it creates no canvas, image fetch, observer, animation loop or decoded-image cache. Navigation resets zoom and scroll. Tests assert bounds, slider changes, no image reread during zoom, reset on navigation and isolation of slider arrow keys from gallery navigation. The existing Slider owns drag listeners, removes them on release, and runs its cleanup on unmount; the viewer adds no document listeners. Live GPU/WebView memory remains unmeasured.

Trackpad follow-up: the previous viewer had no wheel or WebKit gesture listeners. useImagePinchZoom attaches four non-passive listeners only to the mounted image viewport. Ctrl-wheel and gesture scale update the same 25–400% zoom state; ordinary wheel scrolling stays native. A single requestAnimationFrame coalesces bursts, and cleanup cancels it on image change, failure or close. WebKit wheel duplicates during a gesture are ignored. Component tests cover both input paths, event prevention, coalescing and unmount cleanup. React performance guidance was applied to local event scope and frame coalescing. Physical trackpad behavior in Tauri remains unverified without authorized computer control.
