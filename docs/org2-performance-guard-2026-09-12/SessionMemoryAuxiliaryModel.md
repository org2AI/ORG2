## Environment and method

- Apple M3 Pro, 18 GiB RAM, macOS 26.2, battery power. Other user applications and the existing primary/Instance 2 remained running. Memory compression/swap pressure was already present. This is an observational run, not a controlled before/after performance comparison.
- `pnpm run tauri:build:fast -- --instance 3` succeeded. The optimized `dev-build` packaged app used bundle ID `org2ai.org2.instance3`. Executable SHA-256: `ee0ccf67996d4c72441057d990111f99b0c2d884e79997df1da0ae2cf927f4dc`.
- Direct-launched Instance 3 used its existing separate data/auth and external-history homes. The primary and Instance 2 were not restarted. Only a disposable local Git fixture and new test sessions were used; the original session's memory/boundary stayed unchanged.
- All tested agent requests were entered through native computer use. No debug endpoints, fake provider, or seeded memory rows drove these results. Fixture: 900 synthetic text rows, approximately 162 KB, in a local repository with a local bare origin.
- Existing OpenAI OAuth account, selected through the UI: `gpt-5.6-luna-medium`. This is a locally available account, not the issue reporter's specific account.
- Activity Monitor attributed six processes: main, WebKit renderer, GPU, network, ThemeWidget and AutoFill. A local `proc_pid_rusage(RUSAGE_INFO_V2)` sampler measured these six PIDs every two seconds; process start identity guarded reuse. CPU counters were converted with `mach_timebase_info` and cross-checked against `ps` cumulative CPU time. 100% means one CPU core. RSS and physical footprint are summed across the attributed processes; shared resident pages can be counted more than once.
- First-launch setup/native-folder-dialog recovery, stack sampling, and the unsuccessful Raise-only focus-return interval are excluded from the table. Post-team visible idle uses the first 60 seconds: a later two-second bounded SDE post-session reflection ran at 06:24:39 UTC and is excluded from that idle window. Visible idle, Cmd-H hidden idle, native window-close idle and normal Quit were exercised. Cmd-Tab restored the hidden window and a coordinate click successfully reopened the SDE result. Repeated open/close cycles, deletion, account/endpoint switches, offline/reconnect and launcher-created secondary startup were not exercised.

## Audit follow-up: skipped job accounting

Session-memory jobs now return an explicit `Skipped` completion for acquisition cooldown, extraction cooldown, or an extraction that produces no content. The coordinator counts and logs this separately from `Completed`; skipped cleanup clears `extraction_in_progress` without a failure warning. Session-memory `Completed` is returned only after the persistence call succeeds. Other job kinds retain their existing completion semantics: these are process-lifetime job counters, not a universal extraction-success metric.

The debug `/agent/test/memory-metrics` response adds `skipped`; existing fields remain present. This is an additive diagnostic field, with no database or public IPC format change. Reverting the accounting change requires no data migration. The earlier device measurements above are historical observations; their successful extractions also have independent SQLite read-back, and are not inferred from `Completed` alone.

## Cheap-only policy revision

The new policy has at most three candidate strings and a rejection bitmask per session route. A model rejection tries the next cheap candidate within the existing 60-second job deadline. It never adds a timer, polling loop, background worker, or global rejection cache. Exhaustion is silent and counts as `Skipped`; later provider instances retain the rejection set. Account/endpoint/catalog changes reset the route. Session teardown drops the state.

| Background work    | fix     | Parent fallback could spend flagship quota      | Up to three cheap candidates; exhausted and empty lists skip                    | Loopback Luna rejection → Terra → fresh-provider Terra; SQLite unchanged on skips |
