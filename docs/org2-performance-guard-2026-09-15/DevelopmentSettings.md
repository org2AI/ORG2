# Development settings lifecycle review

| Area               | Verdict | Evidence                                                                                    | Change or reason kept                                                                                                      | Verification                                                                          |
| ------------------ | ------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Background work    | keep    | Switch writes a bounded Jotai atom; mocked install exits before coordinator/native services | No added timers, network, IPC, persistence or listeners                                                                    | Service test asserts no check, provenance lookup, install, relaunch or storage writes |
| Memory             | keep    | Two mock booleans and a constant version object per store                                   | Bounded session-only state; intentionally survives settings unmount; turning off clears the mock prompt                    | State isolation and switch remount tests                                              |
| Scope/isolation    | keep    | Availability overlays the real updater state without changing its native Update resource    | Turning off restores real availability; production cannot enable mock; separate stores remain isolated                     | State and production route/navigation tests                                           |
| Rendering/hot path | keep    | Existing availability subscribers see the mock via the same derived atom                    | Sidebar and chat start page need no special rendering paths; unrelated real updater state remains owned by the coordinator | Existing updater and chat start page tests; typecheck                                 |

Lifecycle matrix: startup/idle defaults off and adds no background jobs; active switch invalidates existing UI subscribers; visible/hidden and online/offline add no work; settings unmount retains the switch by design; app restart resets it. Disabling clears mock prompt state. Each window/store is independent. No account, org, provider-history or transport resources are accessed.

Performance verdict: pass for bounded state and absence of new background resources. No CPU/RSS improvement is claimed. Native visual behavior and packaged-build execution were not tested; computer control was not authorized.

Architecture review: compilation, reuse, naming, build-time versus runtime development distinction, fail-closed defaults, UI/service isolation, discovery, and entry-point parity (layers 1–7 and 9). No wire or multi-source resolver changes (layers 8 and 10 inapplicable). Available update metadata is a UI projection; mock data never becomes a native Update object in the coordinator. Every public install action reaches the service mock guard; postponing a mock does not persist a reminder.
