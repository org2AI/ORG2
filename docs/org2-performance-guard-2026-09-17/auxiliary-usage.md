# Auxiliary provider usage attribution

The Package server correctly charges title and memory responses, but native usage previously persisted only the main turn. Title discarded side-query usage, and background memory forks discarded their TurnResult usage. This change records returned provider usage through a transparent auxiliary-only provider decorator, including parser retries and completed iterations before a later failure or cancellation. Existing title behavior, memory settings, provider routing, cancellation, and retry policies remain intact.

The decorator is bound to the parent session, purpose and account. It wraps title, skill/memory prefetch, session/workspace memory, memory consolidation and automatic/manual compaction providers. The shared foreground provider stays unwrapped. Each actual returned response gets a receipt ID. One SQLite transaction inserts the receipt, its parent-session token row and its descriptive LLM span. Replaying the same receipt is idempotent; a different response with the same token counts remains a separate usage event. Aggregates read token rows once, never add spans again. Cache-only responses are retained. No prompt, output or credential is stored; `credential_source` is the existing nonsecret selector, captured from the serving provider.

Native provider normalization remains authoritative: Anthropic input is exclusive of cache, and normalized OpenAI counters are not subtracted again. Reported Anthropic 5-minute/1-hour cache-write counters are preserved when present. No provider usage is invented for errors without a returned response. Processing tier is not available in the current LLMResponse contract and remains unknown. A stream cancelled before any response usage is returned cannot be reconstructed locally. The Market ledger remains authoritative for actual wallet charges; local dollar figures remain list-price estimates, now summed at each row's own model.

Auxiliary rows contribute to lifetime usage and appear by purpose in the existing request table. They do not replace the foreground model or context ring, including after restart and after manual compaction. Legacy rows without receipt metadata retain their previous context fallback. Previously omitted historical usage is not estimated, backfilled, deleted or billed again.

## Migration and recovery

Startup creates the additive `session_auxiliary_usage` table and indexes. Existing token/span columns and their readers remain compatible. Readers tolerate databases without the new receipt table. Session deletion removes receipts and token/span rows; a late response cannot recreate rows for an already deleted session. The receipt transaction is all-or-nothing.

Keep the database backup normally used for an application upgrade. Do not drop the receipt table or delete token rows to roll back: that loses purpose/idempotency metadata or real usage. If reverting the collector, retain the new readers and metadata so existing auxiliary rows still display correctly. An older unpatched reader can sum the token rows, but cannot distinguish auxiliary context rows. Do not restore an old database over newer usage; preserve it for reconciliation with the Market ledger. This change does not alter or migrate the Market ledger.

## Performance and lifecycle review

| Area               | Verdict | Evidence                                                                                              | Change or reason kept                                                                                           | Verification                                                                                                                                                                       |
| ------------------ | ------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background work    | keep    | Existing title/memory jobs own the wrapper; no new timer, retry or provider call                      | Persist once per returned response on blocking pool; an already scheduled write survives caller cancellation    | Provider fixture exercises spawn, subsequent-call cancellation and parser retry; dispatch-then-abort of a blocking write is supported by source lifetime review, not a timing test |
| Memory             | keep    | Immutable session/purpose/account and one normalized usage map per response                           | No app-lifetime cache or queue; DB growth follows existing retained history; session deletion cleans receipts   | Atomic receipt/replay and deleted-session tests                                                                                                                                    |
| Scope/isolation    | fix     | Decorator carries immutable attribution, including for dynamic providers that bypass ReliableProvider | Spawned auxiliary tasks retain parent identity; sharing underlying provider does not attribute foreground calls | Direct and Reliable fixtures, concurrent parents, real local Anthropic HTTP response                                                                                               |
| Rendering/hot path | keep    | Writes happen after responses, not deltas; existing lazy request-table reads show purpose             | Existing indexed per-session queries and bounded table pagination retained; no polling added                    | Post-load regression tests, usage-dashboard round pagination and mixed-model estimate tests                                                                                        |

No ORG2 runtime artifact was built, launched or replaced for this change; no live provider request was made. Native restart/visible-hidden idle measurements and the final Package-to-receipt runtime acceptance remain for the integrated build. Unit fixtures and local HTTP parsing are not a substitute for that acceptance.

Performance verdict: blocked on integrated native runtime measurement; no new unbounded runtime resource identified in source review.
